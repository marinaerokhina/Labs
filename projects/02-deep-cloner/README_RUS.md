# DeepCloner — глубокое копирование объектов

[English README](README.md) · [Все лабораторные](../../)

Небольшая Java-библиотека для копирования объектов и графов ссылок. Основная цель — разобраться с **Reflection API, стратегиями обработки разных типов, аннотациями и расширяемым API**, а не просто скопировать поля через конструктор.

## Возможности

- Универсальная точка входа `Cloner.deepClone(obj)` и создаваемый через `ClonerBuilder` экземпляр клонировщика.
- Обход полей через рефлексию, обработка вложенных объектов.
- Специальные стратегии для массивов, коллекций, `Map`, даты и известных неизменяемых типов.
- Аннотации `@CloneIgnore`, `@ShallowClone` и `@CloneWith` для управления отдельными полями.
- В консольном примере две персоны с адресами и **циклической ссылкой друг на друга**; выводятся проверки некоторых свойств копии.

## Какие паттерны и зачем

**Strategy.** Интерфейс `CloneStrategy` задаёт `supports(type)` и `cloneValue(...)`. Реализации `ArrayStrategy`, `CollectionStrategy`, `MapStrategy`, `DateTimeStrategy` и `IdentityStrategy` отвечают за свою категорию значений. `StrategyRegistry` подбирает подходящую стратегию по типу.

**Builder.** Через `ClonerBuilder` можно добавить собственную стратегию или фабрику экземпляров перед созданием `Cloner`. При этом интерфейс основного сервиса остаётся прежним.

**Factory.** `InstanceFactory` отделяет создание нового объекта от обхода полей. `DefaultInstanceFactory` в типичном случае вызывает конструктор без аргументов через рефлексию.

**Кэш идентичности.** `ClonerService` использует `IdentityHashMap`: прежде чем рекурсивно проходить обычный объект, сохраняет соответствие «исходник → копия». Это позволяет восстановить ссылки назад, например `alice → bob → alice`, без бесконечного обхода при данном пути клонирования.

## Результат

Получилась учебная библиотека с расширяемым API и наглядным демонстрационным примером, а не набором отдельных `clone()` для каждого класса.

## Известные ограничения и проблемы по анализу исходников

- **Циклические коллекции и массивы обрабатываются не полностью.** Специализированная стратегия запускается до регистрации объекта в общем кэше. Самоссылочный список или массив может вызвать бесконечную рекурсию.
- **Поддержка `record` неполная.** Для записи с компонентами стандартная фабрика выбрасывает исключение и предлагает собственную реализацию `InstanceFactory`.
- **`@CloneIgnore` не гарантирует `null`.** Поле пропускается при копировании, но у нового экземпляра может сохраниться значение, заданное инициализатором или конструктором. Так устроено поле `cached` в демонстрационном `Person`.
- При невозможности создать конкретную коллекцию может использоваться другой тип (`ArrayList`, `LinkedHashMap`). Универсальность клонирования для всех Java-типов не гарантируется.
- Отдельных автотестов нет; перечисленные проблемы обнаружены чтением исходников и не все воспроизведены запуском.

## Запуск

Нужны **JDK 21** и Maven. Это **консольный** пример:

```bash
mvn package
java -cp target/classes com.deepcloner.App
```

Компиляция проверяется в [GitHub Actions](../../.github/workflows/maven-labs.yml). Исходный ZIP и отчёт сохранены в [корне репозитория](../../).
